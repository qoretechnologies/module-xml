Root causes and implementation:

- Child extraction retained namespace declarations but discarded inherited
  XML language/space/base properties. Carriers now serialize a separate typed
  inherited-attribute map and compute root context without adding authored
  payload attributes. Older XML-only state remains accepted.
- XML generation and SOAP forwarding apply retained context to the containing
  element. Body/Header contexts are independent; incompatible retained siblings
  and explicit compatibility-header overrides fail instead of changing meaning.
- The initial XML Base implementation used libxml2's ASCII URI resolver, which
  returned no base for a valid Unicode LEIRI such as `rosé`. The final resolver
  parses/merges URI components and removes dot segments without early percent
  encoding/decoding. Unknown relative document bases retain unresolved parents.
- Native attribute generation wrote literal tabs/newlines/carriage returns,
  which XML parsing normalizes to spaces. The encoder now emits character
  references and preserves XML metacharacters, source/output encodings and
  cancellation. This also fixes authored attributes during child extraction.

Requirements: [XML attribute normalization](https://www.w3.org/TR/REC-xml/#AVNormalize),
[language/space inheritance](https://www.w3.org/TR/REC-xml/#sec-lang-tag),
[XML Base](https://www.w3.org/TR/2009/REC-xmlbase-20090128/),
[RFC 3986 resolution](https://www.rfc-editor.org/rfc/rfc3986#section-5.2), and
[XML Infoset element properties](https://www.w3.org/TR/xml-infoset/#infoitem.element).

Open gates and additional findings:

1. The libxml2 namespace-URI ampersand defect and the PCRE2 JIT/valgrind decision
   from earlier checkpoints remain pending. No workaround, suppression or
   production entity-expansion flag was applied.
2. Required valgrind runs use `qore -b --enable-debug`. Native/context suites have
   zero definite/indirect/possible loss, but conditional-read reports remain.
   The final native literal suite reports one context and no lost memory;
   the final context suite reports 175 contexts; the final consumer suite completes
   all 15 cases but reports 7766 errors in 7736 conditional-read contexts and
   384 bytes of possibly lost glibc thread-local storage allocated by the core
   AsyncIoController thread-pool control thread. Definite/indirect loss is zero.
   `--error-limit=no` preserves the complete final reports. This is not a clean
   memory result. The initial consumer valgrind run exceeded a five-second test
   deadline; a bounded 30-second HTTP/queue deadline allows instrumented completion.
3. Minimal async-task and async-XML reproductions have zero valgrind errors/lost
   memory (`/tmp/wsdl-p2-22-async-{pool,xml}-repro.{qr,log}`). A minimal plain-HTTP reproduction without XML or WSDL also succeeds and reports
   352 bytes of possibly lost TLS with zero valgrind errors
   (`/tmp/wsdl-p2-22-http-pool-repro.{qr,log}`). Both HTTP traces allocate the block
   in core AsyncIoController's ThreadPool constructor. This isolates the finding
   to the core HTTP/thread-pool lifetime, with size depending on loaded TLS modules;
   it does not establish that the block is leaked. Core stopWait waits for a
   stopped notification, which precedes the control thread's final native cleanup.
   Complete native-thread termination versus glibc TLS caching still needs
   adjudication before the runtime memory gate can close. No core/astparser code
   was changed.
4. A broader `docs` build exposed **38 additional documentation warnings**, outside
   the affected clean targets. The installed QoreMacros includes packaged SVGs in
   generated `.dox.h` input lists although it generates only Qore sources. Other
   warnings are missing dependency tags, obsolete/wrongly qualified public refs,
   private provider classes referenced as public classes and an undocumented
   WebDAV parameter. Exact warnings are in
   `/tmp/wsdl-p2-22-broad-doc-warnings.log`; these are assigned to P9 documentation/
   packaging acceptance, not silently discarded or claimed warning-free.
5. P3 scalar, P4 particle, P5 wildcard/dynamic semantics and examples, P6/P7 protocol
   and P8 encoding/attachments remain required later phases. P2 has not passed
   its boundary or authorized moving to P3.
