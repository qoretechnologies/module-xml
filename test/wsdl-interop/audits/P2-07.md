## Scope and evidence

Attributed simple content uses its existing `^value^`/`^attributes^` representation.
Hash inputs keep that shape and cannot fall back to scalar conversion. Bare scalar
callers retain their value type when all attributes are optional. Required attributes
require a hash; optional complete values retain required fields when supplied.

Scalar type/choices are reported on the value field. Complete-value choices have an
additive API so the existing raw scalar getAllowedValues() behavior is preserved.
The previous SOAP provider assertion described an attributed element as a string;
its fixture requires an info attribute. The updated test checks the actual structure,
scalar type/choices, accepted values and missing-attribute rejection.

Four new scenarios failed on the parent. Current consumer suite: 12 cases / 137
assertions, including caller immutability, false/zero/empty scalar compatibility,
required/optional variants, negative fields/choices, metadata and Serializable schema
and provider reconstruction. All 322 affected Qore cases pass with debug enabled.
Four independent attribute tests pass; twelve generated payloads now pass through
provider conversion before SOAP 1.1/1.2 serialization in both directions, and exact
typed values/expanded names plus libxml2 and pinned Xerces validation are asserted.

Tests use QORE_MODULE_DIR=/home/david/src/qore/git/qore/qlib to select the rebuilt
core fix without installation. README documents this dependency and invocation.

selected-binding-version subtest failures. Final consumer/SOAP/independent checks
